# 下一阶段建议

> 更新时间：2026-11-07
> 前提：Phase 1 只做 PRD 建模，未连接 ERP、未执行任何 UI 操作。

## 一、收尾状态

1. **Git 首个提交**：已完成。仓库从 `master` 首个提交开始可回溯。
2. **忽略规则**：`dist/`、`test-results/`、`probe/chrome-profile`、`artifacts/` 均已忽略；知识库（含 `rules.json` 约 35.5 MB）为可再生产物，不入库，需要时执行 `npm run prd:scan` 重新生成。
3. **报告一致性**：本报告指标以 `npm run prd:scan` 最近一次运行为准；任何 PRD 或解析逻辑变更后需重跑并同步数字。
4. **PRD 原文档接入**：用例库内 `DOCxxx_<作业>_V<版本>.md` 已按 PRD 建模，并与主目录同名作业归并版本。

## 二、需要外部补齐的数据

34 个用例作业中已有 27 个可建模，剩余 7 个全部属于库存存货域：

1. 品号存货信息、品号批号信息（品号域缺口）。
2. 通用单位换算、存货业务单别、存货单别参数、存货成本分类、维护存货会计分类（存货域缺口）。

另有依赖数据需在进入写入类测试前补齐：业务类型结算参数（对应此前 TP-070 分期保存被 `VD_biz_type_ar_param_00014/00013` 拦截的问题）。

每份补充 PRD 建议保留平台原文档格式（`DOCxxx_<作业>_V<版本>.md`），可直接被扫描器识别；同时补充「业务流程图」与「状态机」章节，否则只能生成字段级场景（当前 143 条流程未随原文档增长，即因流程图章节为空）。

## 三、Phase 2 建议路线

1. **知识库校准**：用真实页面把 8454 个字段的控件类型从候选值收敛为已验证值，优先做本轮已建模的 47 份最新版作业。
2. **场景评审工作流**：3796 条草案需要评审入口（`DRAFT → APPROVED / REJECTED`），并记录评审人与依据；未评审不得进入执行队列。
3. **用例生成器**：以场景 + 知识库生成结构化用例（前置数据、步骤、断言、证据要求），复用现有用例库的 `test-cases.json` 结构。
4. **覆盖率提升**：先解决数据缺口，再优化匹配算法（当前按字段码+规则类型匹配，无法判断语义等价）。

## 四、暂不建议做

1. 不做写操作自动化：当前没有专用测试数据与清理方案，违反仓库只读约定。
2. 不引入外部模型做规则抽取：会破坏「本地处理、可复核」的边界；如确需 AI 辅助，必须可开关、可记录、结果标 `PRD_DERIVED`。
3. 不引入数据库或消息队列：Phase 1/2 的数据量用文件即可承载。
