## 2. 缺口清单

### GAP-01 供应商群组只读（已确认规则，非缺陷）

- 产品规则：**IF 供应商基本信息.供应商编号（`supp_base_info.supp_no`）不为空 THEN 供应商群组只读**。
- 结论：新增时录入供应商编号后群组转为只读，符合设计，**不列为缺陷**。
- 保留建议（S3 体验）：字段由可编辑转只读的 1-2 秒异步窗口建议给出 loading 或“已存在编号，群组不可修改”的提示，避免用户误判。

### GAP-02 通用单位换算无“新增”（已确认：异动即新增，非缺陷）

- 复测：点“异动”进入编辑态后，工具栏出现“新增 / 删除 / 取消 / 保存”，可追加换算行并保存。
- 结论：设计如此，**不列为缺陷**；本轮已按该路径完成 8→9→8 行完整闭环。
- 证据：`probe/p25-unitconv.json`。

### GAP-03 品号属性为子表型页面（已确认结构，非缺陷）

- 复测：新增后主档没有表头字段，属性值在明细行维护（属性值 / 属性值描述 / 备注），保存后列表可见。
- 结论：对象模型如此，**不列为缺陷**；本轮新增 `Z904` 及失效→生效均已通过。
- 证据：`probe/p15-item-attr.json`、`probe/p29-itemattr-status.json`。

### GAP-04 供应商“取消生效”在生效态不可用（一致性提示，不计入未通过项）

- 现象：供应商生效后，行操作/更多菜单仅提供“失效”，未出现“取消生效”；客户同状态下提供“取消生效”。
- 定性：**功能规则不统一提示**。2026-11-09 确认：类似规则不一致只列清单提示，不作为缺陷或未通过项。
- 待确认：供应商是否应支持“取消生效”。
- 证据：`STATE-TRANSITION-MATRIX.csv`、`artifacts/P9-FDN-20261108173328/supplier-life2.json`。

### GAP-05 状态按钮集合随状态变化（一致性提示，不计入未通过项）

- 现象：失效后“编辑”消失、出现“重新生效”；未生效与生效的操作集合不同。
- 定性：**状态机规则不统一提示**，只列清单，不作为未通过项。
- 处理：沉淀为状态机文档并纳入知识库 `confirmed` 规则，供后续用例作前置条件。
- 证据：`STATE-TRANSITION-MATRIX.csv`。

### GAP-06 被引用数据删除/失效拦截（待测试，已排期）

- 现象：本轮未构造“主数据被其它主数据引用”的链路（如计量单位被品号引用）。
- 影响：无法证明删除/失效时的引用保护。
- 定性：**必测项**，纳入下一阶段 B1 批次，见 `docs/plan/下一步测试计划-20261109.md`。
- 验收标准：被引用数据删除/失效必须被拦截并给出明确提示，且数据状态不变。

1. 先修 **DEF-01/03/04**：三处都是“编辑态复用创建态唯一性校验”，建议合并为一次规则修正，否则项目信息、存货参数、采购参数无法维护。

3. 再修 **DEF-05**：失效请求补 `item_feat_no`（可为空串）或后端放宽校验。
4. **DEF-08** 作为 S3 字典/文案问题随版本修正。
5. GAP-04/05 仅作为功能规则一致性提示列出，不计入未通过项；GAP-06 引用保护列入下一阶段必测。
6. 本报告“6 项”只覆盖本轮写入闭环与状态流转口径；`COVERAGE-REPORT.md` 第 7 节的 C-02~C-07 仍未执行，不能据此判定基础管理无其它缺陷。
