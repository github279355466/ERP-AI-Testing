# 基础管理模块缺陷与缺口报告（Gate C）

- 日期：2026-11-09
- 环境：athena-test / digichannel
- 严重度定义：
  - **S0**：数据损坏、不可恢复、越权。
  - **S1**：核心业务链路不可用（登录、单据主流程、跨模块数据错误）。
  - **S2**：单个基础资料功能不可用、数据错误，或存在明确绕行。
  - **S3**：展示、文案、交互一致性问题。

## 1. 缺陷清单

### DEF-01 项目信息编辑保存误报“项目编号已存在”

| 项 | 内容 |
| --- | --- |
| 严重度 | **S2** |
| 页面 | 项目信息 `VTdUTYFuHOdI` |
| 复现步骤 | 1. 新增项目并保存；2. 列表点“编辑”；3. 修改项目名称；4. 点“保存” |
| 实际结果 | 保存按钮变为 disabled；底部错误列表出现 1 条：`UV_ID_07589 项目编号已存在，不可重复！`（前端校验）；名称未保存，列表仍为原值 |
| 期望结果 | 编辑保存成功；唯一性校验应排除当前记录自身 |
| 影响 | 项目信息的新增、查询、删除可用，**编辑完全不可用**；两次独立创建的新记录均可复现 |
| 证据 | `artifacts/P9-FDN-20261108180153/project-defect.json`、`shots/proj-edit-defect.png` |
| 备注 | 创建时唯一性校验正常；仅编辑态误报，判断为更新接口复用了创建态校验 |

### DEF-02 客户通用信息“分店数”默认空值导致后端类型转换异常

| 项 | 内容 |
| --- | --- |
| 严重度 | **S2** |
| 页面 | 客户通用信息 `xwpefqwlWQqi` |
| 复现步骤 | 1. 新增客户，填写客户编号、简称、名称；2. 不填“分店数”；3. 保存 |
| 实际结果 | 弹出“存在可忽视警告”，错误信息：`ConversionException: [cust_base_info][brach_count] property should be INT, but value is`，来源“后端校验”；保存失败 |

| 影响 | 客户新增在默认路径下必然失败；影响所有未填写分店数的用户 |
| 证据 | `artifacts/P9-FDN-20261108175302/customer-crud-v3.json`、`shots/v3-cust-int-error.png` |

## 2. 缺口清单

### GAP-01 供应商群组异步启用且只读，缺少操作提示

- 现象：新增供应商时，输入供应商编号后“供应商群组”仍禁用约 1-2 秒；若立即按 Tab，字段会回退为禁用。启用后可开窗选择，但编辑态始终只读。
- 影响：自动化与用户都可能误判“无法选择群组”；没有加载中或“请先输入编号”的提示。
- 证据：`artifacts/P9-FDN-20261108173204/supplier-create.json`、`shots/supp-saved.png`。
- 建议：确认是否为异步校验设计；增加 loading/禁用原因提示。

### GAP-02 通用单位换算无“新增”，仅有“异动”

- 现象：页面工具栏为“异动 / 筛选 / 导入 / 导出”，行操作为“删除 / ...”，没有新增入口。
- 影响：无法按常规主数据 CRUD 模型验证；需产品说明“异动”是否等价于新增/调整。
- 证据：`FOUNDATION-MODULE-INVENTORY.md`、`artifacts/session-outputs/foundation-button-inventory.json`。

### GAP-03 品号属性新增后无表头字段

- 现象：新增后仅渲染一个子表（属性列），没有“属性编号/名称”等表头字段，无法按常规主数据方式创建。
- 影响：品号属性的对象模型与其它属性页不一致，需产品确认主档与子表关系。
- 证据：`artifacts/session-outputs/foundation-field-inventory-v2.json`（fields=0, grids=1）。

### GAP-04 供应商“取消生效”在生效态不可用

- 现象：供应商生效后，行操作/更多菜单仅提供“失效”，未出现“取消生效”；客户同状态下提供“取消生效”。
- 影响：不同主数据的状态语义不一致，需产品确认供应商是否应支持取消生效。
- 证据：`STATE-TRANSITION-MATRIX.csv`、`artifacts/P9-FDN-20261108173328/supplier-life2.json`。

### GAP-05 状态按钮集合随状态变化，缺少显式规则

- 现象：失效后“编辑”消失、出现“重新生效”；未生效与生效的操作集合不同。
- 影响：用户与自动化都需按状态维护动作白名单，当前只能从界面反推。
- 建议：沉淀为状态机文档，纳入知识库 confirmed 规则。

### GAP-06 被引用数据删除/失效拦截未验证

- 现象：本轮未构造“主数据被其它主数据引用”的链路（如计量单位被品号引用）。
- 影响：无法证明删除/失效时的引用保护。
- 建议：下一阶段用专用数据构造引用链验证。

## 3. 自动化风险（非产品缺陷）

| 编号 | 现象 | 处理 | 影响 |
| --- | --- | --- | --- |
| AUT-01 | 列表行操作存在离屏克隆节点，同一行两套按钮 | 取可见包围盒；下拉用元素级 click | 坐标点击可能命中克隆节点 |
| AUT-02 | “...”下拉有动画，立即查询为空 | 轮询 `offsetWidth>0`，最多 4 秒 | 快速脚本会漏点 |
| AUT-03 | 日期控件不是 `.digi-input` | 适配 `.digi-picker input` | 通用 fill 会超时 |
| AUT-04 | 客户“取消生效”首次复跑未触发，复测 2/2 成功 | 增加点击后状态轮询 | 单次失败不可直接判产品缺陷 |
| AUT-05 | 供应商群组异步启用，Tab 会回退 | 输入后等待启用再开窗 | 早期脚本误判为“群组禁用” |

## 4. 结论与建议

1. 先修 **DEF-01**：编辑态唯一性校验应排除自身，否则项目信息无法维护。
2. 再修 **DEF-02**：分店数默认值或后端空值容错，避免客户新增默认失败。
3. 明确 GAP-01/02/03/04 的产品预期，再决定是否纳入自动化知识库。
4. 将 GAP-05 的状态机沉淀为 `confirmed` 规则，作为后续按钮用例的前置条件。
5. 下一阶段补齐 26 个页面的 CRUD 与引用链验证，重点品号系列、供应商/客户业务与财务信息。
