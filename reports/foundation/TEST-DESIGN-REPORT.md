# 基础管理模块测试设计报告（Gate C）

- 版本：v1.0
- 日期：2026-11-09
- 环境：athena-test / digichannel 租户 / Chrome 157（CDP）
- 测试方式：真实 Web UI 自动化，不直连数据库、不走 OpenAPI、不调用业务 MCP 绕过页面
- 关联资产：`FOUNDATION-MODULE-INVENTORY.md`、`FIELD-RULE-MATRIX.csv`、`BUTTON-INVENTORY.csv`、`STATE-TRANSITION-MATRIX.csv`、`LOOKUP-AND-SOURCE-TARGET-MATRIX.csv`

## 1. 目标

把基础管理模块从“页面能打开”提升为可复用的 ERP 主数据测试模型，验证：

1. 页面、字段、按钮的真实结构与可用条件。
2. 必填、默认值、只读/禁用、唯一性、字段联动等规则。
3. 新增、查询、查看、修改、删除的完整闭环。
4. 生效、失效、取消生效、重新生效的状态流转及按钮副作用。
5. 主数据之间的开窗引用关系（来源对象、回填结果、必填约束）。
6. 异常分支：空必填、重复编码、非法状态操作、默认值导致的保存失败。

## 4. 测试数据策略

- 统一前缀：`ZTEST` + 对象缩写 + 时间戳后 6-8 位，例如 `ZTESTWHSE511710`。
- 每个对象只创建本 run 的数据；删除仅针对本 run 创建且编号匹配 `ZTEST` 的记录。
- 不修改、不失效、不删除他人数据；引用型字段只读取现有主数据（运营单元、供应商群组）。
- 每个动作写入 `artifacts/P9-FDN-<timestamp>/`，包含步骤 JSON 与关键截图。
- 结束后按对象逐条回查编号，确认 `exists=false`；回查结果见执行报告。

## 5. 断言分层

| 层级 | 断言对象 | 示例 |
| --- | --- | --- |
| UI 层 | 提示、错误抽屉、按钮状态、悬浮提示 | 保存后 toast=操作成功；空必填出现“错误列表”；重复编码保存按钮 disabled |
| 业务层 | 列表行字段、状态值、按钮集合变化 | 编辑后列表 `whse_name` 变化；失效后行操作由“编辑/失效”变为“重新生效” |
| 持久化层 | 重新加载列表/详情后的数据一致性 | 重新进入列表并筛选编号，字段值与状态仍为保存后的值 |

不以“点击成功”“页面提示成功”单独判定通过；至少同时满足 UI 提示与列表回读。

## 6. 用例设计模式

- **正向**：最小必填集创建 → 列表回读 → 编辑 → 回读 → 删除 → 确认不存在。
- **负向**：空必填保存、重复编码保存、缺失必填的编辑保存。
- **边界**：默认值字段（金额取位、数据长度、员工人数、分店数）、只读/禁用字段。
- **状态**：生效↔失效、重新生效、取消生效；每次状态变更后检查行操作集合。
- **引用**：开窗选择后回填显示值；必填引用未选择时的前端校验。
- **异常**：默认空值触发后端类型转换异常；编辑态唯一性校验是否排除自身。

## 7. 自动化实现要点与已知抖动

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 行操作离屏克隆 | 同一行存在两套按钮，克隆节点 `x` 为负值 | 优先取可见包围盒；下拉用元素级 click 兜底 |
| 下拉菜单动画 | 点击“...”后立即查询会得到 0 项 | 轮询 `offsetWidth>0`，最多 4 秒，必要时二次点击 |
| 供应商群组异步启用 | 输入编号后约 1-2 秒才解除禁用；按 Tab 会回退禁用 | 输入后等待启用再开窗，不立即 Tab |
| 日期控件 | 不是 `.digi-input`，而是 `.digi-picker input` | 单独适配日期选择器 |
| 筛选默认等于 | 用 `ZTEST` 模糊筛选无结果 | 使用完整编号精确筛选 |
| 取消生效偶发未触发 | 下拉项点击未命中，状态不变 | 复测 2/2 通过，判定为自动化抖动而非产品缺陷 |

## 8. 退出标准

- 页面盘点 100%，按钮清单 100%，关键字段来源可追溯。
- 关键对象 CRUD 全部执行；被缺陷阻断的对象必须有可复现证据。
- 所有写操作有 run id、测试数据前缀和清理核验。
- S0/S1 缺陷为 0；S2 缺陷必须记录复现步骤、错误码与影响。
- 未覆盖项必须写明原因与后续归属，不得以“已开发”推定通过。
