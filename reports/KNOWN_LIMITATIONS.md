# 已知局限（Phase 1）

> 更新时间：2026-11-07
> 用途：说明当前知识模型「能证明什么、不能证明什么」，避免把候选值当成结论。

## 一、数据范围

1. **仍有 7 个作业缺 PRD**：34 个用例作业中 27 个有可建模 PRD（主目录 20 个 + 补充原文档 7 个），剩余 7 个属于库存存货域：品号存货信息、品号批号信息、通用单位换算、存货业务单别、存货单别参数、存货成本分类、维护存货会计分类。覆盖率 18.3% 仍受此缺口影响。
2. **历史副本占比高**：299 份 PRD 中 242 份位于 `_history` / `_diff` / `_review` / `_upload` / `_dup_*`。这些文档被登记和建模，但不参与场景与覆盖率统计。
3. **最新版只有 47 份**：判定规则为「按作业目录分组 + 版本号优先，其次日期」。对同一作业下版本号相同但人工改写的两份文件（主目录与用例库原文档）无法区分先后，只保留其中一份。
4. **补充原文档缺少字段级元数据**：用例库内的 `DOCxxx_<作业>_V<版本>.md` 没有「版本」元数据行，版本号从文件名解析；「数据模型」行也可能缺失，实体主要通过业务对象与标题推断。
5. **补充原文档的流程图章节为空**：新增 27 份原文档的「业务流程图」多为 `*-*` 占位，因此流程（workflows）仍为 143 条，未随文档数增长。
6. **平台 JSON 与 Markdown 重复**：`_upload/*.prd_spec.json` 与同名 Markdown 内容高度重合。当前两者都建模，最新版判定只取其一；若两者内容不一致，不会自动比对差异。
7. **`_diff` 类文档无字段**：差异/体检类文档只被登记，不产生字段与规则。

## 二、解析能力

1. **控件类型为文本推断**：`control_type` 由「填值方式」列的措辞映射（开窗/下拉/日期/数字等），未与真实 DOM 核对，全部应视为候选值。
2. **字段抽取依赖表格结构**：字段来自「字段项 / 详细内容」两列表格；非该结构的表格或纯段落描述不会被识别为字段。
3. **动作抽取依赖固定形态**：只识别 `### 整体操作` / `### 明细操作` 下含「控制项」表头的表格；自由叙述的操作步骤会漏抽。
4. **状态机仅识别两类表头**：`当前状态/目标状态/操作` 与 `状态字段/流转/触发`；其他写法（如纯文字流程描述）不生成 `STATE_TRANSITION`。
5. **流程绑定靠标题层级**：页面（列表页/详情页/页签）由标题文本推断，标题不规范时会归并到上级页面。
6. **DOCX / XLSX / PDF 未实现**：仅有适配接口与预留扩展名，传入这些格式会被记为不支持。
7. **无截断发生**：单文档规则上限 400、字段规则上限 300，实测单文档最多 325 条规则、101 个字段，未触发上限。

## 三、语义判定

1. **规则冲突基于文本比较**：同一实体+字段+规则类型下，描述文本不同即视为差异。跨文档差异记为 MEDIUM，同文档差异记为 LOW。
2. **等价表述未做语义合并**：「无默认值」与「不设默认值」、「隐藏」与「画面不显示」这类同义表述仍会各自成为一条规则，`RULE_CONFLICT` 中 251 条 LOW 多属此列。
3. **推导规则是模板映射**：`PRD_DERIVED` 表示「由操作说明的处理步骤按关键词映射得到」，不等于业务规则已确认，`confidence=DERIVED`。
4. **覆盖率是字段级匹配**：按「字段码/字段名 + 规则类型」与用例断言目标匹配，不判断用例断言口径是否与规则语义一致。覆盖率只用于发现缺口。
5. **流程断链是保守判断**：依赖目标未出现在已建模实体中即记为断链，其中包含参数类字段码（如 `p_supp_no`）与后端表名（如 `pur_stkin_doc_001`），属于真实缺口而非误报，但需要人工归类。
6. **待确认判定靠关键词**：`待确认`、`TBD` 等表述触发 `PENDING` / `AMBIGUOUS`，可能漏掉无关键词的模糊描述。

## 四、工程与产物

1. **`rules.json` 约 35.5 MB**：包含 30641 条规则全文与证据，加载成本较高；暂未提供精简输出或分片。
2. **Schema 校验为自实现**：`src/prd/validate.ts` 做字段级与引用级检查，未引入 JSON Schema 校验器；开发包 `schemas/*.json` 尚未作为运行时约束接入。
3. **增量缓存以 `document_id + sha256` 为键**：文件重命名会产生新 ID 并重建缓存，旧缓存不会自动清理。
4. **扫描状态累积**：`.scan-state.json` 保留历史键；当前 540 个键与 540 个文件一致，但目录结构调整后旧键需手动清理。
5. **Git 仅首个提交**：Phase 1 代码与产物从首个提交开始可回溯，此前的探索过程不在版本历史中。
6. **报表只展示前 100 条**：`OPEN_QUESTIONS.md` 每个分区最多 100 行，完整数据以 `open-questions.json` 为准。
