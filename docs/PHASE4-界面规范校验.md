# Phase 4：界面规范校验

面向 ERP 页面的**界面规范回归**能力。只校验字段与列的排列、顺序、分组与显示格式，不校验业务规则，也不校验颜色/字体/字号/间距等平台统一样式。

## 1. 规范来源

- 规范图：`docs/UI规范/`（单据类列表/详情、基础资料列表/双档详情，以及到货单样例）
- 提取结果：`docs/UI规范/ERP-UI规范.md`
- 机器可读期望：`business-modules/<module>/ui-specs/<page>.yaml`（契约 `platform/contracts/schemas/ui-spec.schema.json`）

## 2. 校验规则

| 规则 | 检查内容 |
| --- | --- |
| L1-03 / L1-04 | 状态标签组排列与「+」新增入口 |
| L1-07 | 批量操作按钮排列（勾选行后读取） |
| L1-09 | 列表列顺序（规范列按序出现，允许扩展列） |
| L1-10 | 「状态」紧邻「操作」且「操作」为最后一列 |
| L1-11 | 编号与名称成对且相邻，禁止列表内含外显 |
| L1-17 | 行内按钮按审核状态呈现，顺序固定 |
| L1-19 | 分页「已选 N 条」与页容量 |
| D2-04 / D2-05 | Banner 单号、合计项数量与组成 |
| D2-07 | 单头分组（基本信息 / 管理信息 …） |
| D2-08 / D2-13 | 字段整体顺序与分组内顺序 |
| D2-10 | 开窗字段显示「名称（编号）」 |
| D2-11 | 开窗组件支持手动输入与名称模糊查询（新增/编辑表单抽样，按字段顺序规避依赖） |
| D2-14 / D2-15 | 明细区与明细列排列 |
| D2-18 | 底部按钮排列 |
| D0-01 / PAGE-RENDER | 详情入口缺失、页面渲染异常 |

判定口径：

- 缺失但可能由状态或列宽「…」收纳引起的，记「待确认」，不直接判失败。
- 出现规范外按钮、顺序颠倒、编号缺名称列，判不符合。
- 页面自身渲染异常（ErrorBoundary、SyntaxError、服务器错误）单独记为 `PAGE-RENDER`。

## 3. 采集与回归

首次接入新页面：

```bash
npm run build
node dist/cli/platform-ui-spec.js run --module <module> --capture --force
```

采集会把**当前实测的列顺序与字段顺序**写入 `ui-specs/<page>.yaml` 作为基线，同时套用模板期望（标签组、批量按钮、行内按钮、Banner、底部按钮）。基线文件属于 `candidate`，需要人工确认后作为回归基准。

日常回归：

```bash
node dist/cli/platform-ui-spec.js run --module purchase,foundation,base,ar,ap
```

## 5. 边界

- 只读：不保存、不提交、不审核、不删除；批量按钮只读取不点击。
- 页面渲染异常或缺少「查看」入口时，记录为不符合/待确认，不猜测页面结构。
- 颜色、字体、字号、间距、列宽不纳入断言。
