## 2. 阅读顺序

1. 先读 `P0-AS-IS.md` 了解“现在是什么”。
2. 再读 `P0-GAP-MATRIX.md` 了解“离目标差什么”。
3. 再读 `P0-MIGRATION-PLAN.md` 了解“怎么迁、先迁什么”。
4. 用 `P0-RISK-REGISTER.md` 和 `P0-DECISIONS.md` 确认风险与需要人工拍板的事项。
5. 用 `P0-ACCEPTANCE-REPORT.md` 核对 P0 是否达到验收标准。
6. 确认后再读 `P1-IMPLEMENTATION-PLAN.md`，决定是否授权 P1。

## 4. 当前一句话结论

现有项目已经具备“PRD 静态建模 + Playwright 只读/受控写入底座 + 采购单证页面对象”的可用基础，但仍是一个“采购示范脚本集合 + 两个并存的子系统”，尚未形成 v2.0 要求的三层平台：没有模块包、没有集成包、没有统一契约治理，采购逻辑已进入 CLI、诊断、页面映射和 PRD 关系/场景等平台核心位置。
