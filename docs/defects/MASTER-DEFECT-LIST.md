> **唯一权威清单。** 单次测试报告、回归报告、验收报告只作为证据来源，不再各自维护「当前是否仍成立」的结论。
> 核对状态只看本文件；报告与本文件不一致时，以本文件及所列证据为准，并回写本文件。

- 最近汇总：2026-11-13
- 环境：athena-test / digichannel / 运营单元 000W1（历史项含 QN001、QN002）
- 范围：功能、数据、流程、字段规则、接口行为、状态流转
- 边界：错误提示语义、单位字典等影响业务判断的文案问题按功能缺陷收录；纯视觉、布局、字号/颜色/间距类问题不收录。
- 不含：UI 规范、视觉、布局、字号/颜色/间距类问题。该类问题单独维护在 `reports/ui-spec/` 与 `docs/PHASE4-界面规范校验.md`，判定口径见 `DECISIONS.md` D-004。
- 约束：本清单不改变 `AGENTS.md` 默认只读约束；复现缺陷需专用测试数据与授权，不得触发未授权的保存、删除、审核、过账。

## 0. 维护规则（强制）

1. 每轮测试结束必须更新本文件：新增缺陷、状态变化、回归结果、撤回依据；不得只写在单次报告里。
2. 单次报告开头写一句「缺陷状态以 `docs/defects/MASTER-DEFECT-LIST.md` 为准」，正文只写本轮新增证据。
3. 新缺陷编号从 `DEF-21` 起顺序分配；历史编号（`DEF-xx`、`OBS-xx`、`DIR-xx`、`GAP-xx`、`BUG-YYYYMMDD-xx`、`AUT-xx`、`D-xx`）保持不变，便于追溯。
4. 状态口径：
   - `未修复`：已复现，产品侧未修。
   - `待确认`：行为已观察到，是否符合设计未定。
   - `待复核`：历史记录，近期未复测，不能直接当作仍成立。
   - `已修复待回归`：产品称已修，尚无回归证据。
   - `已关闭`：已验证修复，或确认非缺陷。
   - `已撤回`：原判定错误，附撤回依据。
   - `阻塞`：环境或数据源缺失，无法判定，不计产品缺陷。
5. 撤回不删行：保留编号、原结论、撤回依据。
6. 同一编号只出现一次；合并项写「并入 XXX」。
