# DEF-20261112-02 应收业务单别删除仍提示被已删除的参数引用

> 总清单编号：**DEF-22**（见 docs/defects/MASTER-DEFECT-LIST.md）。

## 一、基本信息

| 项目 | 内容 |
| --- | --- |
| 缺陷编号 | DEF-20261112-02 |
| 标题 | 应收业务单别 ARAT-01 删除被拦截，提示被“业务类型应收参数 ARAT-01/000W1”引用，但该参数已删除 |
| 严重级别 | 一般（阻塞测试数据清理，不影响业务主流程） |
| 优先级 | P2 |
| 状态 | 待确认（疑似服务端引用缓存未刷新） |
| 发现日期 | 2026-11-12 |
| 发现方式 | 手工 + agent-browser 网络取证 |
| 所属模块 | 应收管理 / 应收业务单别、应收业务单别参数 |
| 运营单元 | 000W1 |

## 二、复现步骤

1. 在「应收业务单别参数」删除 `ARAT-01 / 000W1`，接口 `bm.biz_type_ar_param.delete` 返回 `code=000`。
2. 刷新参数列表：共 11 条，无 `ARAT` 记录。
3. 在「应收业务单别」对 `ARAT-01` 执行删除并确认。

## 三、实际结果

- 删除接口 `bm.biz_type_gen_info.delete` 返回 `code=-1`：
  `当前数据至少被一笔数据引用，无法继续对该数据进行操作。
  【业务类型编号:ARAT-01】：被业务类型应收参数引用 【业务类型编号:ARAT-01，运营单元编号:000W1】`
- 参数列表已确认无该记录，引用提示与现状不一致。
- 间隔数分钟后重试仍相同。

## 四、期望结果

- 参数删除后，单别删除的引用校验应同步失效；或提示仍存在的具体引用记录 ID 与位置。

## 五、影响范围

- 测试数据 `ARAT-01` 无法通过 UI 清理；`ARAT-02` 未验证（删除菜单在共享浏览器中不稳定）。
- 生产场景下若参数删除后仍被判定引用，会影响主数据下线。

## 六、证据

- `bm.biz_type_ar_param.delete` 请求/响应：`agent-browser network request 46008.1182`
- `bm.biz_type_gen_info.delete` 请求/响应：`agent-browser network request 46008.1273`、`46008.1363`
- 参数列表复核：`total=11 arat=0`

## 七、备注

- 本缺陷与 `D-01/D-02`（确认后无请求）不同：本次删除请求真实发出并返回业务错误，属引用校验口径问题。
