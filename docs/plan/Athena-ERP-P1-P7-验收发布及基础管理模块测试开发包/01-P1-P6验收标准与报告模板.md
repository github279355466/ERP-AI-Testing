# P1--P6 验收标准与报告模板

## 验收原则

通过文档检查、代码检查、自动化测试和真实 ERP UI 演练共同验收。区分
PASS、PASS WITH CONDITIONS、FAIL、NOT
VERIFIED。S0=安全/数据范围阻断；S1=核心链路或结果可信性严重问题；S2=一般缺口；S3=优化项。

## P1 平台骨架与契约治理

-   平台核心、适配器、业务模块包、集成测试包、运行配置和执行产物分层清楚。
-   业务规则不硬编码在平台核心。
-   module manifest、scenario、testcase、step、page mapping、data
    recipe、dependency、assertion、execution result 等契约具备 schema。
-   契约具备版本号、兼容策略和自动校验。
-   环境/账号/运行配置与代码分离；凭证不入仓库。
-   执行记录绑定平台、模块包、用例和环境版本。
    证据：目录树、schema、契约测试、代码检索、执行记录。

## P2 PRD与业务知识引擎

-   递归扫描指定 PRD 目录及支持格式，形成文件清单。
-   支持增量扫描，能识别新增/修改文件。
-   抽取模块、菜单、页面、字段、单据、按钮、状态、规则、前后置关系。
-   规则、字段、流程关系可追溯到源文件/页码/段落。
-   冲突规则保留来源并标记待确认，不静默覆盖。
-   未证实内容标 unknown/pending，不允许模型补造确定规则。
    建议抽样准确率≥95%，关键规则来源可追溯率100%。

## P3 场景、用例与依赖编排

-   支持场景、用例、步骤、前置条件、后置条件、断言。
-   依赖 DAG 能表达基础资料、上游单据、状态依赖和执行顺序。
-   能检测循环依赖、缺少前置条件、缺少数据配方/清理策略。
-   Dry-run 展示执行计划和影响范围，不执行真实写操作。
-   用例版本可追溯，执行结果绑定具体版本。
-   编排引擎可供不同模块复用。

## P4 浏览器与数据准备

-   使用 Playwright 真实操作 ERP Web UI。
-   页面适配与业务模块资产分离；优先语义定位，避免脆弱坐标点击。
-   等待以页面可观测状态为主，固定 sleep 不得成为主要同步策略。
-   至少完成一次 UI 创建测试数据的真实闭环。
-   测试数据有唯一标识、组织/账号范围和清理/保留策略。
-   凭证不出现在日志、报告和截图中。

## P5 执行、断言与报告

-   支持依赖顺序执行、跳过、中止、受控重试。
-   断言覆盖页面反馈、字段值、状态、列表/详情一致性和关键关联。
-   失败能区分产品、环境、数据、自动化定位、断言问题。
-   失败步骤保留截图、trace、日志和执行上下文。
-   重试不得无控制地产生重复单据或重复动作。
-   报告包含汇总、用例明细、失败归因、证据和版本信息。
-   可按 execution id 复查。

## P6 示范模块与通用性

-   采购示范模块至少完成一条真实 UI 端到端链路。
-   模块资产包含
    manifest、知识、页面映射、场景、用例、数据配方、套件和断言。
-   有关键异常/负向测试。
-   至少做一个非采购模块的最小接入演练，证明不修改平台核心即可挂载模块资产。若没有，必须列缺口，不能宣称通用性已证实。
-   架构、契约、运行、故障处理和模块接入文档齐备。

## 总体门槛

-   P1--P6必选项通过率100%。
-   S0/S1未关闭问题为0。
-   契约自动校验100%通过。
-   关键知识来源可追溯率100%。
-   关键用例依赖完整率100%。
-   至少一条真实UI端到端链路通过。
-   失败用例证据完整率100%。
-   写操作数据追踪和清理策略覆盖率100%。
-   凭证泄露、非测试环境写操作均为0。

## 报告路径和结构

生成 `reports/acceptance/P1-P6-ACCEPTANCE-REPORT.md`，包含： 1.
执行摘要：commit、分支、版本、时间、结论、问题数。 2.
实现盘点：P1--P6代码路径、入口、测试、最近真实UI证据。 3.
逐阶段矩阵：验收ID、标准、结果、证据、缺口、严重度、整改。 4.
真实UI演练：环境、账号范围、数据准备、操作、断言、截图/trace/日志、清理。
5. 风险缺陷：S0--S3和复验条件。 6. P7准入结论。

禁止：代码存在即通过；单元测试替代UI；mock/dry-run冒充真实测试；删除失败记录美化通过率；未确认环境就执行写操作。
