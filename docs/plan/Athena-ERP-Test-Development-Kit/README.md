# Athena ERP 全功能业务自动化测试平台

**Codex 可执行开发包 | 架构基线 V1.0 | 第一阶段：PRD 扫描建模子项目**

## 1. 本包的定位

本包不是单独的 PRD 文档解析器，而是 Athena ERP 全功能业务自动化测试平台的整体开发基线。第一阶段优先交付 **PRD 扫描与业务知识建模子项目**，同时建立后续自动化测试平台必须遵循的架构边界、数据契约和扩展接口。

本项目以 Playwright UI 自动化为唯一 ERP 业务交互路径：
- 不调用 ERP OpenAPI / MCP 准备测试数据。
- 不调用 ERP OpenAPI / MCP 执行业务操作。
- 不调用 ERP OpenAPI / MCP 验证测试结果。
- ERP 页面是业务操作入口；ERP 页面可观察结果是测试验证依据。
- 允许在经确认的非生产测试环境执行新增、修改、删除、审核、撤审、过账等操作。
- 所有测试数据必须带测试批次标识，并形成可追踪的清理记录。

## 3. 推荐开发顺序

1. **Phase 1：PRD 扫描建模**：先扫描本地完整 PRD 目录，解析、建模、关联、生成场景草案和覆盖率报告。
2. Phase 2：ERP UI 自动化底座：浏览器会话、页面导航、控件适配器、元素定位、诊断能力。
3. Phase 3：测试设计与编排：把结构化场景转成可评审、可执行的测试用例和流程。
4. Phase 4：测试数据管理：批次隔离、数据依赖、数据准备和清理。
5. Phase 5：执行与断言引擎：Playwright UI 执行、业务状态验证、异常恢复。
6. Phase 6：测试管理与报告：批次、日志、截图、Trace、报告、覆盖率和趋势。

不要在 Phase 1 尚未验收时批量编写 ERP 页面测试脚本。

## 4. 快速开始

将本包解压到项目根目录。把所有 PRD 原文放到 `prd/` 下，按业务模块分类，保留原始文件名和版本信息。

随后在 Codex 中打开项目根目录，执行 `CODEX_START_HERE.md` 中的指令。第一轮只允许完成仓库勘察、PRD 扫描建模和报告，不允许直接操作 ERP 环境。

## 5. 当前已知 ERP 页面技术信息

以下信息作为待验证的项目参考，不得当作不可变事实：
- 测试环境：`https://athena-test.digiwincloud.com.cn/`
- 门户为 Angular SPA，业务页面涉及 React / 低代码渲染和 ag-Grid。
- 页面可能使用 `label[for="<entity>.<field>"]` 关联字段。
- 列表可能使用 ag-Grid 虚拟滚动。
- WindowSelect 弹窗可能使用 `.rc-dialog-wrap`。
- 普通下拉可能使用 `.ath-select-dropdown`。
- 可采用专用 Chrome + CDP 供人工登录和探索；Playwright 负责自动化控制、断言、截图和 Trace。
- CDP 仅允许监听 localhost，不得暴露公网。
- 以上选择器和技术特征必须通过当前环境实际 DOM 检查后才能固化到控件适配器。

## 6. 重要原则

- PRD 是业务规则来源，不是所有业务规则都已完整描述。
- 对推导规则必须标记为推导，不得伪装成 PRD 明确要求。
- 页面观察到的行为与 PRD 不一致时，记录差异，不擅自判定哪一方正确。
- 未确认规则必须进入 `OPEN_QUESTIONS.md`，不得编造。
- 先建模、后设计测试、再执行 UI 自动化。
