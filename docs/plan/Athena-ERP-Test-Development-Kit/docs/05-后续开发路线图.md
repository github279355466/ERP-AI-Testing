# 后续开发路线图与阶段门禁

## Phase 1：PRD 扫描与知识建模（本次优先）
交付：扫描器、解析器、知识模型、关联器、质量检查、场景草案、覆盖率和问题报告。
退出条件：PRD 输入可批量扫描；知识模型可校验；规则有来源；冲突和缺失可见。

## Phase 2：ERP UI 自动化底座
交付：
- 浏览器启动/连接/登录会话。
- 门户导航和页面打开。
- 控件适配器。
- 稳定定位策略。
- Grid 虚拟滚动支持。
- Lookup / Dropdown / Modal 交互。
- 截图、Trace、结构化日志。
退出条件：在测试环境中可稳定打开指定页面、识别常用控件并完成受控操作。

## Phase 3：测试设计与编排引擎
交付：
- 场景评审工作流。
- 场景到用例转换。
- 流程 DAG / 依赖排序。
- 前置条件、步骤、断言的数据契约。
- 人工确认状态。
退出条件：一个已评审场景可以形成明确的 UI 操作步骤和可观察断言。

## Phase 4：测试数据管理
交付：
- 测试批次和命名规则。
- 数据依赖图。
- UI 数据准备计划。
- 幂等和重复执行保护。
- 逆序清理计划与清理记录。
退出条件：能创建一组可追踪测试数据，并形成清理计划；未经确认不执行高风险清理。

## Phase 5：自动化执行与断言
交付：
- Playwright 流程执行。
- 断言库。
- 操作风险等级。
- 失败分类、暂停、恢复和安全重试。
- 证据采集。
退出条件：端到端执行一条经评审的业务流程，能输出可复核证据。

## Phase 6：测试管理与报告
交付：
- 测试计划、批次、任务。
- 执行日志、截图、Trace。
- 质量看板和覆盖率。
- 历史回归比较。
- Markdown / JSON / HTML 报告。
退出条件：可管理多模块、多批次测试并追溯每条失败。

## 全阶段门禁

1. 未确认测试环境前，不执行写操作。
2. 未评审场景不得自动执行。
3. 未完成数据依赖检查不得创建业务单据。
4. 非幂等操作不得盲目重试。
5. 删除、审核、撤审、过账等动作必须记录。
6. 结果断言必须有业务依据和可观察证据。
7. 任何阶段不得绕过 UI 调用 OpenAPI/MCP 代替业务操作。
