# 知识模型与数据契约

本文件定义 Phase 1 的最小数据契约。实际 JSON Schema 以 `schemas/` 下文件为准。

## 1. ID 规则

建议使用确定性 ID：对象类型前缀 + 基于规范化来源路径/对象键的稳定哈希。
同一来源重复扫描不得产生新 ID。
跨文档合并实体时保留实体 ID，并维护来源映射。

## 2. 通用字段

知识对象建议统一包含：
- `id`
- `object_type`
- `name`
- `module`
- `status`
- `source_refs`
- `created_by_parser_version`
- `updated_at`

## 5. 证据引用

引用必须定位到实际文档。Markdown 优先保存行号和章节；其他格式保存页码、工作表、单元格或段落位置。若解析器暂时无法定位，必须标记 `EVIDENCE_MISSING`。

## 6. 关联关系

关系对象需表达：
- `source_id`
- `target_id`
- `relation_type`
- `mapping`（有证据才填写）
- `source_type`
- `source_refs`
- `confidence`

关系类型建议：
`USES_MASTER_DATA`、`DERIVED_FROM`、`GENERATES`、`REFERENCES`、`CONSUMES`、`RETURNS_TO`、`STATUS_TRANSITION`、`FIELD_DEPENDENCY`、`CANDIDATE_LINK`。

## 7. 兼容策略

Schema 使用版本字段 `schema_version`。
发生不兼容调整时提升主版本；新增可选字段时提升次版本。
报告必须记录 schema 版本，避免不同批次结果被错误比较。
