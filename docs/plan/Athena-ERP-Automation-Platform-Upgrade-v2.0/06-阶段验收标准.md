# 06 阶段验收标准

## 通用验收规则
- 所有验收均由自动化测试结果、文件产物和可复核证据支撑。
- 不允许只凭 Codex 自述“已完成”判定通过。
- 任何未通过项必须记录缺陷、影响、修复计划和是否阻塞下一阶段。
- 测试环境执行前确认租户/组织/账套/账号范围。
- 禁止将真实密码、Cookie、Token 写入代码、日志或报告。

## P0 验收
| 指标 | 通过标准 |
|---|---|
| 仓库盘点 | 主要目录、入口、依赖、测试、配置均有清单 |
| 旧阶段映射 | 原 Phase 1/2/3 每项成果均有映射 |
| 处理建议 | 每项标注保留/适配/迁移/废弃及理由 |
| 风险 | 高风险项有规避措施和负责人/决策点 |
| 代码变更 | 未获批准前核心代码无破坏性改动 |

## P1 验收
| 指标 | 通过标准 |
|---|---|
| 契约覆盖 | Module、Scenario、TestCase、PageMapping、DataRecipe、Report 均有 schema |
| 校验器 | 正常样例通过，缺字段/错类型/不兼容版本失败 |
| 模块隔离 | 采购业务字段不进入通用 schema |
| 自动化测试 | 契约校验核心路径全部通过 |

## P2 验收
| 指标 | 通过标准 |
|---|---|
| 目录扫描 | 能递归扫描指定模块资料目录 |
| 来源追溯 | 抽取规则可定位原文件和章节/页码/段落 |
| 增量扫描 | 能识别新增、修改、删除文件 |
| 歧义处理 | 冲突和不确定项进入待确认清单 |
| 结构化产物 | 实体、字段、状态、流程、规则和关系可校验 |

## P3 验收
| 指标 | 通过标准 |
|---|---|
| 用例追溯 | 100% 正式用例至少有一个有效来源引用 |
| 审批闸门 | 未批准用例不能进入正式套件 |
| DAG | 正确排序；循环依赖、缺失依赖可检测 |
| Dry-run | 不启动浏览器、不访问 ERP、不写业务数据 |
| 失败传播 | 上游阻塞后下游用例状态正确 |

## P4 验收
| 指标 | 通过标准 |
|---|---|
| Browser Smoke | 能打开目标环境、完成登录并采集证据（凭据由用户安全配置） |
| 页面适配 | 通用控件与模块映射分离 |
| UI 造数 | 造数动作均经 UI 完成 |
| 幂等 | 重跑能识别本次运行数据，避免无意重复创建 |
| 诊断 | 定位失败有截图/trace/定位器信息 |
| 清理 | 清理策略可配置且执行有审计记录 |

## P5 验收
| 指标 | 通过标准 |
|---|---|
| 调度 | 依赖顺序正确，取消/超时状态正确 |
| 断言 | 每条断言保存预期值、实际值和证据引用 |
| 报告 | HTML/JSON/Markdown 至少一种完整报告；建议三种 |
| 失败分类 | 环境、造数、步骤、断言、平台异常可区分 |
| 重试安全 | 非幂等写操作不自动盲目重试 |
| 可复现 | 报告记录平台/模块/用例/环境版本 |

## P6 验收
| 指标 | 通过标准 |
|---|---|
| 采购示范 | 至少一条经评审的采购主流程真实 UI 执行通过 |
| 业务覆盖 | 覆盖范围与 PRD/测试计划一致，未覆盖项透明列出 |
| 数据准备 | 前置资料和上游单据通过 UI 自动准备 |
| 证据链 | 每个关键步骤和断言有证据 |
| 平台纯度 | 无采购专属流程硬编码到平台核心 |
| 第二模块演练 | 新模块可复用相同引擎和契约完成最小接入 |
| 报告 | 能输出模块报告；集成报告能力通过契约/样例验证 |

## M-ONBOARD 验收（每个新模块）
1. 模块 manifest 通过校验；
2. PRD 扫描和知识模型有来源；
3. 页面映射覆盖目标场景；
4. 正式用例经过审批；
5. 数据配方通过 UI 准备；
6. 模块 smoke test 通过；
7. 报告标注模块版本和覆盖边界。

## I-TEST 验收（每条跨模块链路）
1. 所引用模块包版本兼容；
2. 端到端依赖图无环；
3. 跨模块数据传递可追踪；
4. 关键业务状态和金额/数量断言有依据；
5. 中间步骤失败能阻断后续步骤；
6. 报告展示完整链路和各模块子结果。
