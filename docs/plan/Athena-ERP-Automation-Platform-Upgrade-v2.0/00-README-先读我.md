# Athena ERP 自动化测试平台升级开发包 v2.0

## 本包目标

将现有 Athena ERP 自动化测试项目升级为**可扩展的 ERP 自动化测试平台**，而不是采购模块专用脚本集合。

平台采用三层结构：

1. **平台核心（Platform Core）**：通用能力只建设一次。
2. **业务模块包（Business Module Packs）**：采购、销售、库存、应收、应付、生产等模块按统一契约接入。
3. **跨模块集成测试包（Integration Test Packs）**：组合多个模块，验证端到端业务链路。

采购是第一个示范模块，不得把采购业务规则、页面选择器、测试数据写死在平台核心。

## 当前技术边界

- ERP 测试目标：`https://athena-test.digiwincloud.com.cn/`
- 真实业务交互：Playwright 浏览器 UI。
- 当前阶段不通过 ERP OpenAPI、MCP、SQL 直接读写业务数据。
- 测试数据准备也必须通过 UI 完成。
- 环境为测试环境，允许在授权测试范围内执行新增、修改、删除、审核、撤审等动作。
- 所有写操作必须记录执行轨迹；删除、审核、撤审等动作必须由用例显式声明。
- 不得将“测试环境”理解为可以无边界破坏共享数据；执行前仍需确认租户、组织、账套和测试数据隔离策略。

## 使用顺序

1. 将本 ZIP 解压到项目根目录之外的临时位置，先阅读本包。
2. 将整个开发包交给 Codex，或将解压目录作为 Codex 工作区的参考资料。
3. 首次只执行 P0 现状盘点，不允许直接重构。
4. P0 输出差异报告和迁移计划，经人工确认后再执行 P1。
5. 每个阶段完成后按 `06-阶段验收标准.md` 自查，未通过不得进入下一阶段。

## 关键术语

- **平台阶段 P0-P6**：建设和完善平台通用能力。
- **模块接入 M-ONBOARD**：把一个业务模块接入现有平台，不等于重新建设平台。
- **集成测试 I-TEST**：组合多个已接入模块形成端到端业务链路。
- **模块包**：可独立版本化的业务测试资产集合。
- **测试套件**：一组可执行用例及其依赖关系。
