# 08 Codex 阶段执行模板

每次进入一个新阶段时复制本模板，并替换阶段编号。

---

现在执行 **【阶段编号】**。

开始前：
1. 阅读 `00-README-先读我.md`、`01-产品章程与总体规划.md`、`02-总体架构与目录规范.md`、`03-核心数据契约.md`。
2. 阅读 `04-平台建设路线图-P0-P6.md` 中当前阶段内容。
3. 阅读 `06-阶段验收标准.md` 中当前阶段验收要求。
4. 阅读 `docs/upgrade/` 中已批准的现状盘点、迁移计划和架构决策。
5. 检查当前 Git 状态和未提交变更，不得覆盖用户已有工作。

执行要求：
- 只做当前阶段工作，不提前实现下一阶段。
- 先提出实施拆分，再按任务执行。
- 优先增量改造和复用现有代码。
- 任何架构偏差必须写入 ADR/决策记录。
- 不得为通过测试而删除或弱化断言。
- 不得将 Mock/Dry-run 结果伪装成真实 ERP 执行结果。
- 所有业务写操作必须使用受控 Playwright 动作，并保留证据。
- 发现需求歧义时标记待确认，不得自行臆造业务规则。

完成后：
1. 运行相关单元测试、契约测试、集成测试。
2. 输出本阶段变更文件清单。
3. 输出验收指标逐项结果：通过/失败/阻塞/未执行。
4. 输出已知问题、技术债和风险。
5. 更新 README、架构文档、schema 和版本信息。
6. 生成 `docs/acceptance/<阶段编号>-ACCEPTANCE.md`。
7. 给出下一阶段计划，但不得自动开始下一阶段。

停止并等待人工确认。
