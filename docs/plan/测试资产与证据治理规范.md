# 测试资产与证据治理规范（2026-11-11）

## 1. B 级固化到底固什么

### 1.1 两类资产，生命周期不同

| 类型 | 例子 | 生命周期 |
| --- | --- | --- |
| 缺陷回归用例 | DEF-12 出库取单、DEF-15 空税率 NPE | 修复后跑一次确认收敛，之后**长期保留**在回归集中，防止复发 |
| 业务流程用例 | 订单→到货→入库→退货 | 长期资产，每次版本发布/改动都要跑 |

结论：**B 级不是一次性**。修复后跑的那一次是“验收”，之后转为“回归资产”，按发布节奏重复执行。

### 1.2 选择固化对象的三条标准

1. 在主链路上（订单、到货、入库、退货、出库、取价）。
2. 规则稳定、可判定（有明确的期望值或状态）。
3. 会被反复触发（版本升级、参数调整、数据迁移后都要确认）。

不固化：一次性探索、依赖人工判断的体验问题、尚未定稿的规则。

### 1.3 谁来判断

按上面三条我出候选清单，你只做取舍确认；不建议由我单方面决定，因为“是否主链路”属于业务判断。

## 2. artifacts 目录治理

### 2.1 现状（2026-11-11）

- 总计 2,242 个文件 / 2.1 GB。
- 一次性运行目录 135 个 / 1.65 GB，其中 `trace.zip` 93 个 / 1.17 GB。
- 知识类：`knowledge/` 141 MB、`source-index/` 69 MB、`modules/` 84 MB。
- 验收类：`acceptance/` 125 MB。

### 2.2 分类与保留规则

| 类别 | 目录 | 处置 |
| --- | --- | --- |
| 可复用资产 | `knowledge/`、`source-index/`、`modules/` | **保留**，属于平台运行依赖 |
| 里程碑证据 | `acceptance/`、报告引用过的 run 目录 | 保留最近一次，旧的压缩或删除 |
| 临时证据 | 其余 `2026xxxx-xxxx` run 目录 | 保留最近 7 天；`trace.zip` 默认删除 |

### 2.3 清理动作（需确认后执行）

1. 删除所有 `trace.zip`（约 1.17 GB）：`Get-ChildItem artifacts -Recurse -Filter trace.zip | Remove-Item`
2. 删除 7 天前的 run 目录（约 1.5 GB 剩余部分）。
3. 保留：`knowledge/`、`source-index/`、`modules/`、`acceptance/`、`session-outputs/`，以及被报告引用的 run。

`artifacts/` 已在 `.gitignore` 中，清理不影响仓库。

### 2.4 artifacts 与 agent-browser 的关系

- **artifacts 不是执行方式**，是证据落盘位置；agent-browser 是操作通道。两者不冲突。
- 后续执行仍可用浏览器自动化，但默认只保留：失败截图、DOM、错误码、请求摘要；完整 trace 仅失败时保留一份。

## 3. 缺陷清单机制（每次跑完必更）

每次执行结束按固定动作收口：

1. 更新 `reports/CONSOLIDATED-BUG-LIST-20261110.md`（新增/撤回/状态变化）。
2. 更新对应批次报告的“未完成项/阻塞项”。
3. 输出三段话：本轮通过项、仍未通过项、需人工复测清单（含单据号与入口）。
