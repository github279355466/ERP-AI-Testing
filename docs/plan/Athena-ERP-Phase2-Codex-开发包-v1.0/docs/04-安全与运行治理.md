# 安全与运行治理

## 1. 环境隔离

- 只允许明确登记的非生产 ERP 主机/域名。
- 环境配置必须包含 `environmentName`、`baseURL`、`environmentType`。
- `environmentType` 仅允许 `development`、`test`、`staging`；`production` 一律拒绝。
- 启动前展示目标环境并要求确认。
- 域名白名单和生产黑名单双重校验。
- 禁止通过重定向跳转到白名单外主机；导航过程中持续检查 origin。

## 2. 高风险操作

以下动作默认关闭：
- 审核、撤审
- 删除
- 过账、结账
- 批量更新
- 影响库存/财务/生产状态的操作

启用必须满足：
1. 用例明确列出动作；
2. 测试环境经过确认；
3. 配置显式启用；
4. 运行前再次确认；
5. 记录操作者、时间、runId、单据标识和动作结果。

第一条采购订单 E2E 建议只做新增、保存、查询和读取断言。

## 3. 凭据与敏感数据

- `.env`、storageState、Cookie、Token 不得提交版本库。
- 日志不得记录密码、认证头、Cookie、完整个人信息。
- 截图和 Trace 可能含业务数据，应限制目录权限并设置保留周期。
- 默认本地保存，不自动上传外部存储。
- 测试账号使用最小必要权限，不复用生产账号。

## 4. 副作用与幂等

- 点击“保存”前检查是否已存在本次 runId 的测试标记，防止重复创建。
- 失败后不得盲目重试新增、删除、审核等动作。
- 每次运行记录预期副作用和实际副作用。
- 清理动作单独授权；不能默认认为删除是安全的。
- 若 ERP 无法删除已保存单据，应采用经业务确认的作废/撤审/隔离策略。

## 5. 证据管理

每次运行建立独立目录：

```text
artifacts/runs/<runId>/
  manifest.json
  logs/
  screenshots/
  traces/
  reports/
```

manifest 至少包含：
- runId
- startedAt / finishedAt
- environmentName / environmentType / baseURL（必要时脱敏）
- testCaseId
- knowledgeModelVersion
- codeCommit
- operator
- createdDocumentIdentifiers
- outcome
- evidenceFiles

## 6. 网络与 API 禁令

禁止通过任何 HTTP/API/数据库通道完成 ERP 业务动作或验证。仅允许浏览器正常加载 UI 页面所需的网络活动。自动化代码不得主动调用 ERP API、复用内部接口、构造业务请求或从响应体读取业务结果来代替页面断言。
