# Phase 2 有序验收指标

## 1. 验收规则

每个子阶段独立验收，结论只有：
- **通过**：全部硬性指标满足，可进入下一阶段。
- **有条件通过**：无安全/数据完整性阻塞项；遗留项明确、低风险，用户书面确认后可进入下一阶段。
- **不通过**：存在安全门禁失效、证据不可追溯、关键功能失败或核心指标不达标，必须整改复验。

“未验证”不等于“通过”。真实 ERP 未验证时，不能宣称真实环境验收通过。

## 2. P2.0 验收：项目基线与安全门禁

| 指标 | 目标 | 验收方式 | 性质 |
|---|---:|---|---|
| 仓库与依赖审查 | 100%形成清单 | 审查报告 | 必须 |
| Phase 1 输入版本 | 明确且可校验 | 读取版本/manifest | 必须 |
| 未授权连接阻断 | 100%阻断 | 不配置授权变量运行 | 硬门槛 |
| 生产环境阻断 | 100%阻断 | 使用模拟生产 URL 测试 | 硬门槛 |
| 高风险操作默认关闭 | 100%关闭 | 配置测试 | 硬门槛 |
| 凭据日志泄露 | 0 次 | 日志扫描与测试 | 硬门槛 |
| runId 唯一性 | 每次运行唯一 | 连续运行测试 | 必须 |
| 运行 manifest | 100%生成 | 检查产物 | 必须 |

P2.0 任何硬门槛失败均不通过。

## 3. P2.1 验收：浏览器、会话、登录、导航

| 指标 | 目标 | 验收方式 |
|---|---:|---|
| 浏览器生命周期测试 | 100%通过 | 自动化测试 |
| 登录流程 | 测试环境连续 5 次成功 | 真实 UI 验证 |
| 页面导航 | 指定页面连续 5 次到达 | 真实 UI 验证 |
| 会话失效识别 | 5/5 正确识别 | 模拟与真实测试 |
| 登录失败诊断 | 100%产生原因和证据 | 故障注入 |
| 失败截图/Trace | 100%按配置生成 | 故障注入 |
| 凭据脱敏 | 0 个明文秘密 | 日志/证据扫描 |
| 超时控制 | 所有等待均有上限 | 静态检查+测试 |

如未获得测试账号，真实登录和导航标记“未验证”，不得宣称 P2.1 完整通过。

## 4. P2.2 验收：控件适配器

| 指标 | 目标 | 验收方式 |
|---|---:|---|
| 适配器契约 | 100%有参数/返回/异常定义 | 代码审查 |
| fixture 测试 | 每种已实现控件至少 3 个场景 | 自动化测试 |
| 真实 ERP 控件验证 | 采购订单实际涉及控件 100%覆盖 | 真实 UI |
| 操作前可见/可用检查 | 100%核心操作具备 | 代码审查+测试 |
| 操作后状态验证 | 100%有必要的后置检查 | 代码审查+测试 |
| 固定坐标核心操作 | 0 个 | 代码扫描 |
| 无限制重试副作用操作 | 0 个 | 代码审查 |
| 超时和错误上下文 | 100% | 故障注入 |

控件覆盖范围应以真实采购订单页面为准，不得为了凑齐清单而虚构 ERP 使用了某种控件。

## 5. P2.3 验收：页面对象与知识模型映射

| 指标 | 目标 | 验收方式 |
|---|---:|---|
| Phase 1 模型版本校验 | 100%执行 | 自动化测试 |
| 页面对象关键字段映射 | ≥95% | 页面核对 |
| 控件类型映射准确率 | ≥95% | 真实页面抽样 |
| 未映射字段登记率 | 100% | 差异报告 |

## 6. P2.4 验收：采购订单端到端验证

| 指标 | 目标 | 验收方式 |
|---|---:|---|
| 登录及导航 | 1 条完整成功链路 | 真实 UI E2E |
| 采购订单新增 | 至少 3 次独立运行成功 | 真实 UI E2E |
| Lookup 选择与回填 | 100%核对 | 页面读取 |
| 明细行输入 | 关键字段 100%核对 | 页面读取 |
| 保存后重新查询 | 3/3 成功 | 真实 UI E2E |
| 关键字段断言 | 100%通过 | UI 读取断言 |
| runId 与单据关联 | 100% | manifest/报告 |
| 失败证据完整率 | 100% | 人为制造失败 |
| 非 UI 后端访问 | 0 次 | 代码审查/网络审计 |
| 未授权高风险操作 | 0 次 | 审计记录 |
| 数据清理策略 | 已评审并演练 | 人工确认 |

关键字段至少包括：单据编号、供应商、日期、品号、数量、单价（如适用）、明细行数及可观察的单据状态。实际字段以 PRD 和测试环境页面为准。

## 7. 全阶段最终门槛

进入 Phase 3 前，必须满足：

1. P2.0 至 P2.4 验收报告齐全。
2. 安全门禁无未解决硬缺陷。
3. 采购订单 UI E2E 在授权测试环境通过。
4. 保存后重新查询和业务字段断言通过。
5. 证据、运行日志和数据批次可追溯。
6. Phase 1 与实际页面的差异已登记并完成业务评审。
7. 运行手册、配置说明和故障排查文档齐全。
8. 所有未验证项明确列出，用户确认是否接受。

## 8. 缺陷等级

- S0 阻断：可能连接生产、越权操作、泄露凭据、误删/误过账、绕过 UI。
- S1 严重：核心登录/保存/查询/断言失败，证据缺失，数据无法追踪。
- S2 一般：部分控件或异常处理不完整，有明确临时规避且不影响安全。
- S3 优化：可维护性、日志可读性、性能或文档优化。

S0/S1 未关闭不得通过。S2 是否允许有条件通过需用户确认。S3 可进入后续迭代。
