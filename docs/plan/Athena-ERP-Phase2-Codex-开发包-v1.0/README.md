# Athena ERP 自动化测试平台 — Phase 2 开发包

版本：V1.0  
阶段名称：ERP 页面自动化底座（Playwright UI Automation Foundation）

## 1. 本包目标

在 Phase 1 的 PRD 扫描与业务知识建模成果基础上，建设稳定、可复用、可观测、可审计的 ERP 页面自动化底座。Phase 2 只建设“能稳定地通过 UI 操作 ERP”的能力，不承担完整测试管理平台，也不批量开发全部业务模块测试用例。

**唯一 ERP 业务交互路径：Playwright UI。**

严禁使用 ERP OpenAPI、MCP、数据库直连、SQL、内部服务接口等方式准备业务数据、执行 ERP 业务操作或验证业务结果。允许 Playwright 自身的浏览器协议能力用于 UI 自动化；不得绕过 UI 访问 ERP 后端接口。

## 2. 交付范围

- Phase 2.0：现有项目审查、运行基线、环境与安全门禁
- Phase 2.1：浏览器、会话、登录、导航、证据采集底座
- Phase 2.2：ERP 通用控件适配器
- Phase 2.3：页面对象与 PRD 页面模型映射
- Phase 2.4：采购订单端到端 UI 技术验证

## 3. 非目标

- 不重新实现 Phase 1 PRD 扫描建模。
- 不在本阶段开发全 ERP 的完整测试用例库。
- 不建设微服务、消息队列、向量数据库或复杂分布式调度。
- 不使用 API/MCP/SQL 代替 UI 操作。
- 不在生产环境运行。
- 不默认自动执行不可逆操作；审核、撤审、删除、过账等高风险动作必须有独立授权与门禁。

## 4. 使用方式

1. 解压本包到项目工作区，或将包内文件合并到现有 Athena 项目文档目录。
2. 将全部 PRD 放在项目配置指定目录；Phase 2 读取 Phase 1 已评审并冻结的知识模型，不重复扫描原始 PRD。
3. 将 `CODEX_START_HERE.md` 全文交给 Codex。
4. Codex 必须先审查当前代码库与 Phase 1 交付物，再提出差异清单和执行计划；经用户确认后按阶段实施。
5. 每个子阶段完成后先运行验收，未通过不得进入下一子阶段。

## 5. 关键工程原则

- 先适配真实 ERP 页面，再写业务操作。
- 优先使用用户可见、稳定、语义化定位器；避免脆弱的绝对 XPath、固定坐标和长 CSS 链。
- 所有操作必须有超时、错误上下文和证据。
- 每个测试运行有唯一 runId；测试数据操作必须记录批次和对象标识。
- 页面对象封装业务页面；控件适配器封装通用控件，不混淆职责。
- PRD 页面模型是预期规格，不是实际 DOM 的事实；必须通过真实测试环境侦察并记录差异。
- 失败不能自动重试有副作用的操作，除非已证明幂等或有明确恢复策略。
- 认证凭据、Cookie、Token、个人信息不得写入日志、截图报告或提交到版本库。
