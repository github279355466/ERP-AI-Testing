# Phase 3 字段规则校验要求（先行清单）

> 状态：**只沉淀要求，本轮不执行**。平台升级后按本清单统一建用例、统一执行。
> 本文件不改变 Phase 2 的验收结论；Phase 2 只覆盖「流程贯通 + 输入回填一致性」。

## 1. 定位与使用方式

- 一条规则 = 一个用例；标记 P1 的规则必须同时具备正例与反例。
- Oracle 优先级：PRD 章节 > 系统参数/单别参数配置 > 现场观察。
- 现场观察只能产出 `candidate` 规则，必须经人工评审后才能转为 `confirmed`。
- 反例的判定标准：出现明确阻断提示，且单据不落库、状态不前进。

## 2. 范围

| 单据 | 单别 | 备注 |
| --- | --- | --- |
| 采购订单 | PO0501 | 单价、金额、数量、项目、默认值源头 |
| 采购到货单 | PO0602 | 扣已到货量、发票类型、仓库 |
| 采购入库单 | IM0301 | 扣已入库量、仓库、储位、批号、过账 |
| 采购退货单 | PO1102 | 可退量、占用量、单价只读性 |
| 采购退货出库单 | IM0402 | 金额/税额比例折算、取单扣减、储位 |

字段域：单价、金额与税额、数量与单位、项目、仓库、储位、批号与效期、币别与汇率、主数据默认值、跨单据数量控制、状态与可编辑性。

## 3. 断言分层

| 层 | 内容 | 观测方式 |
| --- | --- | --- |
| L1 UI | 字段可见/隐藏、可编辑/只读、必填星号、提示语 | 页面 DOM 语义与可见状态 |
| L2 业务 | 页面可观察的计算结果（金额、税额、可退量、状态、过账状态） | 详情页字段值 |
| L3 持久化 | 保存后重查、列表行、下游单据取值 | 仅通过 UI 重查，不使用 API/SQL |

## 7. 验收口径

- P1 规则：100% 有正例与反例。
- P2 规则：至少正例，反例可按风险抽样。
- 每条规则输出一行结果：规则ID、正例结果、反例结果、证据路径。
- 失败必须留截图 + DOM + 提示原文；阻塞记 `blocked`，跳过记 `skipped`。

## 8. 与 Phase 2 的关系

- Phase 2 覆盖：登录、导航、控件操作、单据新增、保存、重查、流程状态流转。
- 本清单覆盖：字段级业务规则与计算口径，属 Phase 3「测试设计与编排」。
- 平台升级完成后，先按第 6 节确认阻断是否解除，再批量执行本清单。
