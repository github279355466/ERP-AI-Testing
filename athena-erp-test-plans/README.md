# Athena ERP 独立作业测试计划集

## 1. 编制依据

本测试计划集依据用户提供的《鼎捷雅典娜（athena-test）页面元素分析报告》编制。

- 环境：`https://athena-test.digiwincloud.com.cn/`
- 页面架构：门户 Angular SPA + 低代码渲染应用（React + ag-Grid）
- 业务页由页面设计元数据驱动
- 页面字段优先通过 `label[for="<entity>.<field>"]` 定位
- 列表采用 ag-Grid，需考虑虚拟滚动
- WindowSelect、Select、Switch、Input 等控件按报告中的实际发现设计
- 代理与 CDP 参数以本机实际环境为准；报告记录 CDP 端口 9333、代理 127.0.0.1:10808

## 2. 计划拆分原则

共生成 **73 份独立测试计划**，按报告可见的菜单叶子作业逐一拆分。每个计划可独立执行、记录结果和归档证据。

- `TP-002 存货参数`：报告提供了该作业的实体、18 个字段（含系统字段）、控件类型、选择器和页面行为，故增加作业专属测试用例。
- 其他作业：报告只提供菜单名称，未提供各自的页面字段、设计元数据和业务规则。因此计划先包含页面探索、只读验证、控件识别与待确认项；禁止 Codex 臆造字段、规则和接口。
- 报告提及的 `outputs/menu-tree.json`、`outputs/field-dict.json` 等附件并未包含在本次上传文件中，因此没有据此扩充菜单或字段。

## 3. 安全边界

当前计划按只读测试编制。不得点击保存、保存并新增、删除、审核、反审核或其他写入/高风险按钮。报告明确要求关闭未保存页签时选择“直接离开”。任何写入型测试必须另行授权并补充测试数据与清理方案。

## 4. 目录结构

- `plans/`：每个 ERP 作业一份独立测试计划。
- `templates/`：计划模板。
- `knowledge/`：作业计划清单及机器可读索引。

## 5. 建议 Codex 执行顺序

1. 先执行 `TP-002 存货参数`，验证页面识别和只读测试框架。
2. 按模块逐个执行其他计划的页面探索与只读测试。
3. 每完成一个作业，将真实菜单路径、workItemCode、页面设计元数据、字段字典、控件和截图回填该作业计划。
4. 业务规则必须经页面元数据或业务负责人确认后，才能升级为正式断言。
5. 未经批准不执行写入测试。
