# TP-027 / TP-038 / TP-039 / TP-047 / TP-051 / TP-052 采购域前置数据与执行顺序测试计划

- 版本：v0.1

- 目标：先建立采购域测试所需的主数据与源单，再执行目标作业，避免供应商/品号/源单为空导致中途阻断
- 机器可读清单：`knowledge/purchase-prerequisite-plan.json`

## 1. 背景与现状

上一轮测试中，三支单据在运营单元 000W1 下“选择供应商”开窗均为 0 行，导致询价单、采购退货单、采购退货出库单无法新增；供应商品号价格同样在供应商开窗处阻断。

结论：问题不在脚本，而在前置主数据缺失。必须先建立供应商，再建立品号、业务单别、取价数据和源单，最后才能跑目标单据。

## 2. 依赖关系

```
P0 运营单元 / 货币 / 仓库 / 批号编号规则
        │
P1 供应商（通用/业务/财务） + 品号（通用/采购/批号）
        │
P2 采购业务单别 + 采购取价策略 + 供应商品号价格
        │
P3 采购订单 → 采购入库单
        │
P4 询价单
P5 采购退货单（依赖 P3 入库单）
P6 采购退货出库单（依赖 P5 退货单）
```

采购取价服务无独立作业，不在本计划内；后续通过询价单/采购单据取价场景验证。

## 4. 分阶段执行与门禁

### P0 组织与公共基础

- 依赖：无
- 创建/确认 运营单元：000W1（运营单元（现有））
- 创建/确认 货币：CNY（货币信息）
- 创建/确认 仓库：WH-QA01（仓库信息）
- 创建/确认 批号编号规则：BRL-QA01（批号编号规则）
- 门禁：G0：000W1、CNY、WH-QA01 查询均 >=1 行

### P1 供应商与品号

- 依赖：P0
- 创建/确认 供应商：SUP-QA01（供应商通用信息/业务信息/财务信息）
- 创建/确认 品号：ITEM-QA01（品号通用信息/采购信息/批号信息）
- 门禁：G1：四页供应商开窗 >=1 行；品号开窗 >=1 行

### P2 业务单别与取价

- 依赖：P1
- 创建/确认 采购业务单别：INQ-QA01 / RTN-QA01 / RSO-QA01（采购业务单别）
- 创建/确认 采购取价策略：PS-QA01（采购取价策略）
- 创建/确认 供应商品号价格：000W1+SUP-QA01+ITEM-QA01+CNY+一般采购（供应商品号价格）
- 门禁：G2：三支单据单别开窗 >=1 行；供应商品号价格可保存

### P3 源单：采购订单与采购入库单

- 依赖：P2
- 创建/确认 采购订单：PO-QA01（采购订单）
- 创建/确认 采购入库单：PR-QA01（采购入库单）
- 门禁：G3：采购退货单取单开窗可查到 PR-QA01

### P4 询价单

- 依赖：P2
- 创建/确认 询价单：INQ-DOC-QA01（询价单）
- 门禁：G4：询价单可保存并完成流程

### P5 采购退货单

- 依赖：P3
- 创建/确认 采购退货单：RTN-DOC-QA01（采购退货单）
- 门禁：G5：退货单可保存并完成流程

### P6 采购退货出库单

## 5. 预检清单

每次执行前先做只读预检，任一门禁为 0 行即停止，不得继续写入。

| 门禁 | 检查项 | 通过标准 |
| --- | --- | --- |
| G0 | 运营单元/货币/仓库 | 各 >=1 行 |
| G1 | 四页供应商开窗 | 各 >=1 行 |
| G1 | 品号开窗 | >=1 行 |
| G2 | 三支单据单别开窗 | 各 >=1 行 |
| G3 | 退货单取单 | 可查到已审核入库单 |
| G4-G6 | 单据流程 | 状态按预期流转 |

当前已知缺口：供应商开窗 0 行（证据：`artifacts/session-outputs/TP-027-052-purchase-evidence/*-supplier-lookup.png`）。品号/货币需在供应商补齐后继续预检。

## 6. 数据清理

按反向依赖顺序清理：采购退货出库单 → 采购退货单 → 采购入库单 → 采购订单 → 供应商品号价格 → 采购取价策略 → 采购业务单别 → 品号 → 供应商 → 批号编号规则 → 仓库。

- 清理前先查引用；被引用记录先解除引用或保留并登记。
- 禁止直接改库；清理失败登记到 `docs/TODO.md`。
- 单据类优先用“作废/删除”标准流程清理。
